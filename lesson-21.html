Lesson 21 · Computing the posterior: Markov chain Monte Carlo

Part V · Bayesian modeling

Why posteriors are sampled, the Metropolis algorithm, Hamiltonian Monte Carlo, the effect of parameterization, and convergence diagnostics: trace plots, R-hat and effective sample size.

About 3 hours Before this: Lessons 19–20 Threads: uncertainty · frequentist ↔︎ Bayesian

By the end of this lesson you will be able to

  • explain why posteriors are computed by sampling rather than on a grid;
  • run the Metropolis algorithm by hand, and explain the role of the step size;
  • describe how Hamiltonian Monte Carlo (the method in Stan) uses the posterior’s slope to move efficiently;
  • explain why centering predictors helps samplers;
  • read trace plots, R-hat and effective sample size, and recognize a sampler that has not converged.

Why it matters. The grids of Lesson 19 work for two parameters. A DLNM has dozens and a spatial model hundreds, and a grid with 100 points per parameter would need more points than there are atoms in the universe. Markov chain Monte Carlo instead wanders through the parameter space, spending time in each region in proportion to its posterior probability. Every Bayesian result in Part V depends on this working, so it pays to know what failure looks like.

21.1 The Metropolis algorithm

The Metropolis algorithm is a random walk with one rule. From the current value, propose a jump of random size. If the posterior is higher there, move. If it’s lower, move only with probability equal to the ratio of the two heights; otherwise stay put. Over many steps, the chain visits each value in proportion to its posterior density. Here it samples the risk of asthma from 30 cases in 200 children, with a Beta(2, 18) prior, so the exact answer is known for comparison.

AStandard notation

\[\theta^* \sim \mathrm{Normal}(\theta^{(s)}, \sigma^2_{\text{step}})\] \[\theta^{(s+1)} = \begin{cases} \theta^* & \text{with probability } \min\!\left(1, \dfrac{p(\theta^* \mid y)}{p(\theta^{(s)} \mid y)}\right) \\ \theta^{(s)} & \text{otherwise} \end{cases}\]

BModel list and R

log_post <- function(p) if (p <= 0 || p >= 1) -Inf else
  dbinom(30, 200, p, log = TRUE) + dbeta(p, 2, 18, log = TRUE)
theta <- numeric(5000); theta[1] <- 0.6
for (s in 2:5000) {
  prop <- rnorm(1, theta[s - 1], 0.03)
  accept <- log(runif(1)) < log_post(prop) - log_post(theta[s - 1])
  theta[s] <- if (accept) prop else theta[s - 1]
}
NoteR code (optional): a Metropolis sampler checked against the exact posterior 
set.seed(21)
log_post <- function(p) if (p <= 0 || p >= 1) -Inf else
  dbinom(30, 200, p, log = TRUE) + dbeta(p, 2, 18, log = TRUE)
theta <- numeric(5000); theta[1] <- 0.6
for (s in 2:5000) {
  prop <- rnorm(1, theta[s - 1], 0.03)
  theta[s] <- if (log(runif(1)) < log_post(prop) - log_post(theta[s - 1])) prop else theta[s - 1]
}
kept <- theta[-(1:500)]                       # discard warm-up
rbind(metropolis = quantile(kept, c(.025, .5, .975)),
      exact      = qbeta(c(.025, .5, .975), 2 + 30, 18 + 170))
#>                 2.5%       50%     97.5%
#> metropolis 0.1019709 0.1433161 0.1947115
#> exact      0.1021411 0.1443794 0.1948669
mean(diff(theta) != 0)                        # acceptance rate
#> [1] 0.6325265

Further reading: Metropolis et al. (1953) introduced the algorithm; Hastings (1970) generalized it; Gelman et al. (2013) on Markov chain simulation for posteriors.

21.2 Hamiltonian Monte Carlo and the shape of the posterior

With two or more correlated parameters, a random walk struggles: proposals that move along the narrow ridge of the posterior are rare. Hamiltonian Monte Carlo (HMC), the method behind Stan and brms, uses the slope of the log posterior to glide along it, like a frictionless puck on a curved surface, making long moves that are still likely to be accepted. Compare the two samplers on the Lakeside heat model of Lesson 19, with temperature centered at 20°C or left uncentered.

AStandard notation

\[H(\theta, r) = -\log p(\theta \mid y) + \tfrac12 r^\top r\] \[r \leftarrow r + \tfrac{\epsilon}{2}\nabla_\theta \log p(\theta \mid y), \quad \theta \leftarrow \theta + \epsilon\, r, \quad r \leftarrow r + \tfrac{\epsilon}{2}\nabla_\theta \log p(\theta \mid y)\]

The last line is one leapfrog step, repeated L times per iteration; \(r\) is a random momentum.

BModel list and R

# brms / Stan use an adaptive HMC (NUTS):
fit <- brms::brm(visits ~ I(temp - 20),
                 family = poisson, data = d,
                 chains = 4, iter = 2000,
                 warmup = 1000)

Further reading: Betancourt (2017) is an accessible introduction to HMC; Hoffman and Gelman (2014) introduced the No-U-Turn sampler used by Stan; Carpenter et al. (2017) describe Stan.

21.3 Has it converged? Trace plots, R-hat and effective sample size

A sampler gives no warning on its own when it fails. Standard practice runs several chains from different starting points and checks that they agree. Trace plots should look like overlapping, well-mixed “hairy caterpillars”. R-hat compares variation between and within chains; values above 1.01 signal trouble. The effective sample size (ESS) says how many independent draws the correlated chain is worth.

chain 1chain 2chain 3chain 4

AStandard notation

\[\hat R = \sqrt{\frac{\frac{N-1}{N}W + \frac{1}{N}B}{W}}, \qquad \text{ESS} = \frac{M N}{1 + 2\sum_{k \ge 1}\rho_k}\]

\(W\): average within-chain variance; \(B\): between-chain variance (× \(N\)); \(M\) chains of length \(N\) (after splitting each in half); \(\rho_k\): autocorrelation at lag \(k\).

BModel list and R

summary(fit)            # Rhat, Bulk_ESS, Tail_ESS
bayesplot::mcmc_trace(fit)
posterior::summarise_draws(fit)
WarningCommon pitfall

Reporting results from a model with R-hat above 1.01, low effective sample sizes, or divergent-transition warnings. These aren’t cosmetic: they mean the draws may not represent the posterior. Fix the model (reparameterize, center predictors, use better priors) before interpreting it.

TipBayesian preview

The hardest posterior shape for samplers is the funnel that appears in hierarchical models when the group-level SD is small: a narrow neck where the step size must be tiny, opening into a wide mouth. Stan flags it with divergent transitions. Lesson 24 shows the funnel and the standard cure, the non-centered parameterization.

Further reading: Gelman and Rubin (1992) introduced R-hat; Vehtari et al. (2021) give the improved rank-normalized version used by Stan today; Gabry et al. (2019) on diagnostic plots in the Bayesian workflow.

Key takeaways

  • Grids are infeasible beyond a few parameters; MCMC samples the posterior instead.
  • Metropolis accepts uphill moves always and downhill moves sometimes. Step sizes too small or too large both make it inefficient.
  • HMC uses the posterior’s gradient to make long, well-aimed moves; Stan’s NUTS tunes it automatically.
  • Centering predictors reduces posterior correlation and helps every sampler.
  • Run several chains; check trace plots, R-hat (≤ 1.01) and effective sample size before interpreting results.
